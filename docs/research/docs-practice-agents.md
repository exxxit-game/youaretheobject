## Item 1: instruction file, imports, path-scoped rules

### 1a. Tool makers
- Anthropic, Claude Code docs "How Claude remembers your project", https://code.claude.com/docs/en/memory (live doc, fetched 2026-10-14; mentions v2.1.281, so current).
  - Size: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence."
  - Imports do NOT save context: imports "don't reduce its context cost, because imported files also load at launch." Startup warning appears when a file is over recommended length AND "when files that are each within that length add up past a combined limit"; "Each CLAUDE.md, rules file, and @path import counts as a separate file."
  - Not enforcement: "Claude treats them as context, not enforced configuration. To block an action ... use a PreToolUse hook". CLAUDE.md is "delivered as a user message after the system prompt"; "no guarantee of strict compliance, especially for vague or conflicting instructions."
  - When to add: "Claude makes the same mistake a second time"; "the same correction ... that you typed last session".
  - What belongs: "facts Claude should hold in every session"; multi-step procedures or part-of-codebase rules go to a skill or path-scoped rule.
  - Consistency: "if two instructions contradict each other, Claude may pick one arbitrarily"; review "periodically to remove outdated or conflicting instructions"; `/doctor prompt-audit` looks for "instructions written for older models, references to files or commands that don't exist".
  - Path rules: rules with `paths` frontmatter "only load into context when Claude works with matching files"; rules without paths load at launch like CLAUDE.md. Import depth max "four hops".
  - Must-run steps: "If the instruction is something that must run at a specific point ... write it as a hook instead."
  - Fit to us: our CLAUDE.md (~5 KB) is fine alone, but the three always-imported files (~13 KB + ~4 KB + one more) are all at-launch context; Anthropic says imports do not reduce cost. Path-scoped rules match the recommendation.
- Anthropic, "Best practices for Claude Code", https://code.claude.com/docs/en/best-practices (live doc, fetched 2026-10-14; mentions v2.1.283, current).
  - Pruning test: "Would removing this cause Claude to make mistakes?" If not, cut it. "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!"
  - Exclude: "Information that changes frequently", "Long explanations or tutorials", "Anything Claude can figure out by reading code".
  - Symptom of too long: "If Claude keeps doing something you don't want despite having a rule against it, the file is probably too long and the rule is getting lost."
  - "Treat CLAUDE.md like code: review it when things go wrong, prune it regularly, and test changes by observing whether Claude's behavior actually shifts."
  - Emphasis: "If you emphasize many lines, none of them stands out."
  - Failure pattern "The over-specified CLAUDE.md": "Claude ignores half of it because important rules get lost in the noise." Fix: "Ruthlessly prune. If Claude already does something correctly without the instruction, delete it or convert it to a hook."
  - Hooks: "Unlike CLAUDE.md instructions which are advisory, hooks are deterministic and guarantee the action happens."
  - Verification (items 3/5): Stop hook as "deterministic gate"; verification subagent "so the agent doing the work isn't the one grading it". Reviewer "sees only the diff and the criteria you give it, not the reasoning". Caution: "A reviewer prompted to find gaps will usually report some, even when the work is sound"; "Chasing every finding leads to over-engineering"; tell reviewer to flag only gaps affecting correctness/stated requirements.
  - Writer/Reviewer: "A fresh context improves code review since Claude won't be biased toward code it just wrote."

### 1c. Research on instruction files
- Gloaguen, Mündler-Sasahara, Müller, Raychev, Vechev (ETH Zurich / LogicStar), "Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?", arXiv:2602.11988, v1 2026-02-12, v3 2026-09-29 (ICLR 2026 listing). Abstract page (opened in browser): https://arxiv.org/abs/2602.11988 ; full text v3 (via WebFetch, small-model extraction): https://arxiv.org/html/2602.11988v3 . Fits: yes (Claude Code + Sonnet 4.5, Codex GPT-5.2; Python tasks only).
  - Abstract v3: "providing context files does not generally improve task success rates, while increasing inference cost by over 20% on average"; holds "for both LLM-generated and developer-committed context files"; "repository overviews, although popular and recommended by model providers, are not helpful"; context files "useful for specifying non-standard coding practices".
  - Numbers (v3 full text, via WebFetch extraction): developer files +2.4 points, p=0.21 (not significant); LLM-generated -0.5 (SWE-bench Lite) and -2 points (CTXbench), not significant; cost +20%/+23% for LLM files, up to +19% for developer files; instructions ARE followed (uv used 1.6x per task when mentioned vs <0.01 when not); "no clear relationship between context file length and success rate or cost" (extraction; not checked against PDF).
  - Recommendation: files "should only contain specific additional instructions beyond what is already available in the codebase".
  - Note: v1 (Feb 2026) reported developer files +4 points; v3 softened that to not significant. Cite v3.
  - Relevance to us: rules our agent follows literally cost extra steps; overview text (project layout) is the least useful kind; non-standard practices (no build step, no Playwright locally, Russian texts only in texts.ru.js) are the useful kind.
- Jaroslawicz, Whiting, Shah, Maamari (Distyl AI), "How Many Instructions Can LLMs Follow at Once?" (IFScale), arXiv:2507.11538, 2025-07-15, NeurIPS 2025 listing. https://arxiv.org/html/2507.11538v1 (full text via WebFetch extraction). Fits: partly (models up to Claude 4 / o3; task = keyword inclusion in a report, not coding).
  - "even the best frontier models only achieve 68% accuracy at the max density of 500 instructions."
  - Table (avg 5 runs): claude-sonnet-4 94.4% at 100 instructions, 77.2% at 250, 42.9% at 500; claude-opus-4 94.6% / 67.9% / 44.6%; o3 98.2% / 97.8% / 62.8%.
  - Primacy bias: later instructions violated more; ratio peaks around 150-200 instructions. Errors shift to omission (instruction simply dropped) as count rises.
  - Limitation (authors): "simple keyword-inclusion instructions", may not generalize.
  - Relevance: adherence falls with instruction count even in strong models; the drop is omission (silently not doing it), which is what a "rule for every mistake" file risks.
- Ting Yan, "When 'Do Not' Is Not Deny: Security Rules in CLAUDE.md vs Built-In Controls", arXiv:2608.23550, 2026-08-24 (cs.HC, v1, preprint). https://arxiv.org/abs/2608.23550 (abstract only read; numbers from abstract = unverified against full text). 481 public CLAUDE.md files; about 4-16% of written security rules had a built-in enforcing control (strictest about 4.4%). Argues CLAUDE.md is a "write-only channel": authors get no feedback whether anything enforces a rule. Relevance to items 3/4: supports pairing each written prohibition with an enforcing control (deny rule or hook). Fits: yes.
- Chatlatanagulchai, Li, Kashiwa, Reid, Thonglek, ..., Adams, Hassan, Iida, "Agent READMEs: An Empirical Study of Context Files for Agentic Coding", arXiv:2511.12884, v1 2025-11-17, v2 2026-08-09. https://arxiv.org/abs/2511.12884 (abstract only). 2,303 context files, 1,925 repos. Files evolve through "frequent, small additions", "like configuration code", "not static documentation"; called "complex, difficult-to-read artifacts". Security in 14.8%, performance 14.5% of files. Relevance: confirms the drift pattern (growth by accretion) seen in practice. Fits: yes.
- Chatlatanagulchai, Thonglek et al., "On the Use of Agentic Coding Manifests: An Empirical Study of Claude Code", arXiv:2509.14744, 2025-09-18. https://arxiv.org/html/2509.14744v1 . 253 Claude.md files from 242 repos; content: Build and Run 77.1%, Implementation Details 71.9%, Architecture 64.8%, Testing 60.5%. Rot not measured: "Future work could examine the evolution and decay of Claude.md files." Fits: descriptive only (Claude Code early 2025).
- Lulla, Mohsenimofidi, Galster, Zhang, Baltes, Treude, "On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents", arXiv:2601.20404 v2 2026-03-30. https://arxiv.org/html/2601.20404v2 . Codex CLI + gpt-5.2-codex, 10 repos, 124 PRs, paired with/without. Median runtime "Δ 28.64%" lower (98.57 s to 70.34 s); output tokens 16.58% lower; total tokens about unchanged (+1.29%). Correctness NOT measured ("beyond the scope of this paper"). Relevance: efficiency gain, not quality evidence. Fits: yes (Codex).

## Item 3: "a rule for every mistake" (mistakes file)
- Tool makers say add a rule on a REPEATED mistake, not every mistake: Anthropic memory doc "Claude makes the same mistake a second time" (https://code.claude.com/docs/en/memory); Cursor "Add rules only when you notice Agent making the same mistake repeatedly" (https://cursor.com/docs/context/rules).
- Anthropic best practices: if the rule exists and is still broken, "the file is probably too long and the rule is getting lost"; fix: "delete it or convert it to a hook" (https://code.claude.com/docs/en/best-practices). => Our "mistake only with its automated guard" matches the maker's advice to convert rules to hooks.
- Cherny (Claude Code creator) adds a line per mistake (VentureBeat 2026-01-04) BUT also says delete every 3 months and add back one at a time (Threads 2026-01-05). The accumulation is the known failure, reset/ablation is the counter.
- Rajasekaran (Anthropic, 2026-03-24): harness parts encode what the model can't do and "can quickly go stale as models improve" — counters written against an older model's failures may be dead weight after a model change.
- IFScale (2025): adherence falls with instruction count; errors become omissions.
- Anthropic Academy, "A CLAUDE.md that follows" (course "Claude Code in action"), https://academy.claude.com/courses/claude-code-in-action/a-claude-md-that-follows (footer 2026; fits: yes). Names the accumulation cycle: "You hit a problem, you add a rule. You hit another, you add another rule." Then the file grows until Claude ignores parts. "Every line competes with every other line for Claude's attention." Fix: "Move your hard rules to hooks and let CLAUDE.md handle the softer conventions."; "If you can't justify a line, delete it."; "The leaner the file, the more of it Claude actually follows."
- Manpreet Singh, "Why Claude Code ignores CLAUDE.md, and what sticks", DEV, 2026-10-09, https://dev.to/manpreet171/why-claude-code-ignores-claudemd-and-what-sticks-2595 (practitioner with data: 175 sessions, 3,817 messages, 323 corrections, 12 projects). Four causes: rule never written; rule for something else; rule was "a wish" (uncheckable, e.g. "Explain simply"); rule clear but still broken (timestamp rule in a 311-line file: 4 guessed timestamps in 24 days, one fix commit titled "for the third time"). What worked: PreToolUse hook that refuses the call; caveat: hooks enforce only what a script can check, "a hook which only adds text is still just a request" (paraphrase via extraction). Fits: yes, very close to our setup.
- Tian Pan, "Your CLAUDE.md Is Probably Too Long (And That's Why It's Not Working)", 2026-02-14, https://tianpan.co/blog/2026/02/14/writing-effective-agent-instruction-files (practitioner blog; fits yes). "past a certain size, adding more instructions causes the model to follow fewer of them."; "The typical response — adding more rules, or adding emphasis to existing ones — makes things worse." Prune test: "Has Claude violated this rule in the past month? If no, consider whether it's still relevant."; "Instruction files should be pruned the same way you'd prune dead code."; root file "40-80 lines"; root "references these files by name but doesn't embed their content".

## Item 4: hooks at session start, guards blocking commands
- Anthropic, "Automate actions with hooks" (hooks guide), https://code.claude.com/docs/en/hooks-guide (live doc, fetched 2026-10-14; mentions v2.1.210+; current).
  - Purpose: "deterministic control: certain actions always happen rather than relying on the LLM to choose to run them."
  - SessionStart: "Claude Code adds plain text your command writes to stdout to Claude's context." Use matcher `compact` "to re-inject critical context after every compaction". But: "For injecting context on every session start, consider using CLAUDE.md instead." (i.e. a SessionStart print that duplicates CLAUDE.md is double cost; memory doc also says to remove a SessionStart hook that prints AGENTS.md once it's read directly: "the hook adds a second copy to the context").
  - Guards: PreToolUse exit 2 or JSON `permissionDecision: "deny"` cancels the call and feeds the reason back to Claude. A hook deny "blocks the tool even in bypassPermissions mode".
  - Limitation: Bash pattern matching "is best-effort, use the permission system rather than a hook to enforce a hard allow or deny."
  - Hook-injected text "is injected as a system reminder that Claude reads as plain text" (= advisory again, like CLAUDE.md).
  - Stop hook: Claude Code "overrides a Stop hook after it blocks eight times in a row"; check `stop_hook_active`.
  - InstructionsLoaded event can log which CLAUDE.md/rules files load and why (useful to check path-scoped rules actually load).

## Item 5: subagents as independent reviewers
- Anthropic, "Create custom subagents", https://code.claude.com/docs/en/sub-agents (live doc, fetched 2026-10-14; first 100k of 110k chars read).

## General (tool maker principles)
- Anthropic Engineering, Rajasekaran, Dixon, Ryan, Hadfield, "Effective context engineering for AI agents", 2025-09-29, https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents (fits: yes).
  - Goal: "the minimal set of information that fully outlines your expected behavior."
  - Against rule-lists: teams "stuff a laundry list of edge cases into a prompt" — "We do not recommend this." Two failure modes: "hardcoding complex, brittle logic" vs "vague, high-level guidance".
  - "context rot": recall declines as context fills. CLAUDE.md "naively dropped into context up front"; other files fetched just in time.
  - Item 2: structured note-taking: agent "regularly writes notes persisted to memory outside of the context window" (to-do list, NOTES.md).
- Anthropic memory doc, auto memory section (https://code.claude.com/docs/en/memory), relevant to items 2 and General:
  - One place: auto memory "skips anything it can derive from the codebase, such as architecture, file paths, or debugging fixes. It also skips anything your CLAUDE.md files already say." Project notes = "decisions that Claude can't derive from the code or git history".
  - Index pattern: `MEMORY.md` is an index, "one line per memory"; detail in topic files read on demand. Load limit: "The first 200 lines of MEMORY.md, or the first 25KB"; near the limit Claude Code reminds Claude to "keep one line per entry, move detail into topic files, and merge or drop stale entries"; past it "everything past the limit is dropped on the next load".

## General: dated vs timeless wording

## SUMMARY (end of run)
Item 1. Good: path-scoped rules; specific, checkable rules; rules with a reason; pointers not copies. Bad/at risk: always-imported files count as launch context (Anthropic: imports "don't reduce its context cost"); >200 lines per file reduces adherence; accumulation; repository overviews add cost without benefit (Gloaguen 2026); emphasis everywhere = none.
Item 2. Good: JSON pass/fail list + short free-text notes + git (Anthropic). Bad: appended logs mix stale with current; agents flip "passes" without real evidence unless a gate forces it (cwc repo). Counter: rewrite current state, prune completed items (Huntley), evidence-gated writes.
Item 3. Good: guard-backed lessons = maker advice "convert it to a hook"; verified addition beats add-all (Xiong 2025). Bad: "a rule for every mistake" is the named failure (Anthropic Academy; Cherny's "directive bloat" exchange); counters for old models go stale (Rajasekaran 2026, Anthropic prompting guide).
Item 4. Good: PreToolUse deny is the only reliable block; CI as backstop. Bad: SessionStart prints that repeat CLAUDE.md double the cost; bare deny rules bypassed by command variants; agent bypassed hooks via --no-verify/stash (#40117).
Item 5. Good: separate, read-only, fresh-context judge; artifact-checkable criteria; duplicate reviewers + confidence filter (Anthropic code-review plugin). Bad: custom subagents load CLAUDE.md by default (not blind) unless omitClaudeMd; gap-finders invent gaps; same-model self-preference; in-band judges accept regressions (Park 2026).
