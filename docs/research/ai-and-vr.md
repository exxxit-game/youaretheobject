### A3. Papers (2023-2026): LLMs that generate or edit VR/XR scenes, apps and code

- Du, Hersh et al., "Vibe Coding XR: Accelerating AI + XR Prototyping with XR Blocks and Gemini", arXiv:2603.24591, Mar 2026; paper [read: related work and Table 1]. https://arxiv.org/html/2603.24591 . VCXR60 pass@1 (zero-error run in an automated runtime test, 5 runs): gemini-3.1-pro high thinking 95.5% at median 86.02 s; gemini-3-flash low 87.4% at 17.30 s; earlier versions "an approximate 70% pass rate". Its related work lists the authoring line: LLMR (De La Torre et al., 2024) and DreamCodeVR (Giunchi et al., 2024), which "generate spatial objects and scenes in Unity"; Thing2Reality (Hu et al., 2025); the commercial tool Bezi; Ubiq-Genie (Numan et al., 2023), which "exposes AI services to Unity-based XR applications"; DreamGarden (Earle et al., 2025), "LLM-driven hierarchical planning to generate functional 3D game environments" in Unreal.
- Wang, Zhao, Mao, Yang, "Survey of Large Language Models in Extended Reality: Technical Paradigms and Application Frontiers", arXiv:2508.03014, Aug 2025; paper [read: first 100,000 characters]. https://arxiv.org/html/2508.03014v1 . Surveys "over fourty representative works" 2019-2025. Authoring systems named: LLMER (Chen et al., 2025; LLM writes JSON scene specs for Unity XR), LLMR (CHI 2024; GPT-4 Planner/Builder/Inspector modules edit XR scenes in real time), MagicItem (LLM DSL compiled into game logic), Text2VRScene (IEEE VR 2024), VRCopilot (UIST 2024), DreamCodeVR (IEEE VR 2024, spoken descriptions to C# Unity scripts run live). It does not treat LLMs as tools for psychology experiments and does not cover LLMs testing VR apps.
- LLMER, arXiv:2502.02441, 2025 [seen]: the LLM outputs JSON instead of scripts to reduce crashes from flawed code; Unity, deployed on commercial headsets. https://arxiv.org/html/2502.02441
- XARP Tools, arXiv:2508.04108, 2025 [seen]: an XR toolkit in Python "agent-ready"; an agent writing XR apps in Python compared with one writing equivalent Unity C# on 14 tasks, measured in tokens. https://arxiv.org/html/2508.04108
- "Harnessing large language models for virtual reality exploration testing: a case study", Automated Software Engineering (Springer), 2025 [seen]: an LLM drives automated testing of VR apps. https://link.springer.com/article/10.1007/s10515-025-00535-3
- Common thread of the papers: the LLM builds a scene or a prototype inside a research system, measured in a simulator or a short user study; none describes an LLM coding agent as the sole developer of a whole shipped game over months with a non-programmer.

### A2. Platform makers who build VR with AI agents themselves (Meta)

- Meta, "IWSDK AI-assisted dev tooling", Horizon OS docs, last updated 2026-03-10; documentation [read]. https://developers.meta.com/horizon/documentation/web/iwsdk-ai-assisted-dev-tooling . Meta's own WebXR SDK (IWSDK, MIT, Three.js + ECS) ships an agent loop for Claude Code: the agent "connects to an MCP server running inside the Vite development server via stdio"; 32 MCP tools (session, device control, observation, scene inspection, ECS debugging) drive IWER, the headset emulator, so "no headset required"; a Quest is optional "for on-device testing"; a RAG server over the SDK, six Claude Code skills and a generated PROJECT_CLAUDE.md. Known trap named there: a missing LocomotionEnvironment is "the #1 cause of bugs". The agent tests in the emulator, not in the headset.
- Meta, "Accelerate VR Development with AI & Immersive Web SDK", Horizon developer blog, 8 Apr 2026; post [read]. https://developers.meta.com/horizon/blog/accelerate-vr-development-with-ai-and-immersive-web-sdk/ . Meta rebuilt its WebXR gardening app Project Flowerbed with the agent loop, "rebuilt from the ground up in only 15 hours", reusing old art; the AI "writes code, tests interactions, and fixes bugs alongside you"; lesson stated: closing the loop with validation is "essential for high-quality, reliable results". How it was tested on the device and what failed: not said.
- Meta, "What Unity Developers Learned About Building for Meta Quest at Unite Seoul 2026", blog, 22 Jul 2026; post [read]. https://developers.meta.com/horizon/blog/unite-seoul-2026-meta-quest/ . Two internal prototypes "built almost entirely through AI-assisted agentic workflows": Arcade Hoops "from idea to playable beta in two days", Neon Reach VR playable in one day, "ready in three days total". Loop: a prompt, the agent writes code, builds the scene and "validates the result inside XR Simulator", then human prompts and manual edits. Tools: Meta VR CLI, Unity MCP, Meta XR Operator; 32 open agent skills. Novel mechanics "still benefit from hands-on iteration". No failures reported (a vendor showcase).
- Meta's Unity tutorial series uses Claude Code in every example (Unity 6.3, Unity MCP; the agent "can read the scene, modify objects, run play mode, and inspect components") [seen in search only]: https://developers.meta.com/horizon/documentation/unity/unity-tutorial-ai-vr-setup/
- Google, Ruofei Du and Benjamin Hersh, "Vibe Coding XR: Accelerating AI + XR prototyping with XR Blocks and Gemini", Google Research blog, 25 Mar 2026 (paper and CHI 2026 demo); post [read]. https://research.google/blog/vibe-coding-xr-accelerating-ai-xr-prototyping-with-xr-blocks-and-gemini/ . Gemini Canvas + the open XR Blocks framework (WebXR, three.js) turns a prompt into a WebXR app for Android XR in "under 60 seconds". Evaluation VCXR60: 60 prompts from 20 Google employees; one-shot success = zero errors in the desktop simulator; early versions about 70% success. Stated limits: the evaluation is preliminary; XR needs on-device testing and human judgment that it does not capture; early failures from framework bugs and "hallucinated or deprecated APIs"; the simulator does not replicate headset-only features. German coverage: heise, "Gemini generates VR apps in under a minute" (German) [seen]: https://heise.de/-11226287
- Meta, agentic tools for Quest (GitHub meta-quest/agentic-tools; the Horizon Debug Bridge CLI hzdb, now "Meta VR CLI (metavr)", with an MCP server); docs [seen in search: https://developers.meta.com/horizon/essentials/ai-tooling-overview/ ]; French press article [read]: realite-virtuelle.com, "Meta Agentic Tooling for VR: the AI revolution on Meta Quest" (French, date not shown) https://www.realite-virtuelle.com/meta-agentic-tooling-for-vr-la-revolution-ia-sur-meta-quest/ . Agents (Claude Code, Cursor, Copilot, Gemini CLI) get a bridge to the physical headset: install and launch apps, screenshots, logs, files, and "can retrieve a complete system trace" (French, translated) with Perfetto; skills such as hz-perfetto-debug, hz-xr-simulator-setup, hz-store-submit; a local index of Meta's docs. This is the same toolset our studio uses (metavr, hz-* skills). So an agent measuring a real Quest is offered by Meta to everyone; what is not documented anywhere I found is a team using it as the routine check of every change.
- PICO (ByteDance), developer platform news list [read in the browser pane: https://developer-cn.picoxr.com/en/pico-os-6/ , page title "Use AI to develop spatial apps"]: posts "PICO Partners with TRAE IDE to Explore a New AI-Native XR Development Workflow" (2026-05-07) and "PICO CLI 0.5.0 Is Now Live: Build Your First Spatial App with One Sentence" (2026-09-15). The posts themselves not read [seen]. The Chinese platform maker goes the same way as Meta and Google.
- Note for judging closeness: since spring 2026 the maker of our headset itself presents "an AI agent writes and tests the VR app" as the normal path. In all Meta's examples the agent checks in an emulator or simulator; on-device testing is optional and done by a person. Our agent's measuring in the real headset over USB (tools/quest-look.mjs, metavr, OVR Metrics) goes further than these published loops; Meta's own metavr CLI and skills make it possible, so it is not unique in kind.

## B. Psychology experiments in VR offered to the public

- VERA (Virtual Experience Research Accelerator), Gottsacker, Bruder, ... Bailenson, Welch; arXiv:2609.26203, 4 Sep 2026; paper [read: library copy objekt-files/papers/gottsacker-2026.txt, sections I-IV]. A cloud research platform: a web app for study design plus a Unity plugin; the study is "published as a WebXR application and assigned a unique distribution URL"; participants are recruited through Prolific and play "on their own consumer HMD", unsupervised. The study is cybersickness (N=263), not a classic psychology experiment as a game. Its own positioning: closest relatives are RemoteLab (supervised remote sessions over video) and Ouvrai ("supports unsupervised WebXR studies but requires each research group to host its own backend"). No AI/LLM in its build or run is stated. Differs from us: a tool for researchers with paid recruited participants, not a public game; built in Unity by a lab team.
