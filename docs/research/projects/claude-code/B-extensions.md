# B. Claude Code extensions (hooks, skills, subagents, plugins, MCP) judged for "You are the object"

Sources: official docs at https://code.claude.com/docs/en/<page>.md, read 2026-10-09.
Installed CLI here: 2.1.268; newest: 2.1.295 (per coordinator, changelog). Features that need a newer version are marked [needs > 2.1.268].
Pains: P1 repeats mistakes / claims unchecked things / shortcuts; P2 long sessions, compaction loses requests; P3 owner must not check anything; P4 data protection; P5 cost and speed.

## 1. Hooks (hooks-guide.md, hooks.md)

Key facts quoted from the pages:
- Why hooks: "deterministic control: certain actions always happen rather than relying on the LLM to choose to run them" (hooks-guide).
- Hook types: `command`, `http`, `mcp_tool`, `prompt`, `agent`; "Agent hooks are experimental and may change" (hooks-guide).
- Exit 2 = blocking; "Without valid JSON on stdout, Claude Code treats exit code 1 as a non-blocking error and proceeds with the action... If your hook is meant to enforce a policy, use `exit 2`" (hooks.md).
- FAIL-OPEN today: "A timed-out `command`, `http`, or `mcp_tool` hook doesn't block the tool call... don't count on a stalled hook to act as a gate"; "A hook that can't start lands in the same non-blocking bucket... a mistyped path in `settings.json` leaves the gate silently disabled" (hooks.md). The `onFailure: "block"` field (coordinator: changelog 2.1.295 "a hook that can't start, times out, or exits with an unexpected code blocks the action") is NOT yet described on hooks.md or hooks-guide.md (I searched all three chunks of hooks.md: no "onFailure"). [needs > 2.1.268]
- Context cap: "`additionalContext`, `systemMessage`, and `initialUserMessage` strings, and its plain stdout, are capped at 10,000 characters" (hooks.md).
- Reload: "If you edit settings files directly while Claude Code is running, the file watcher normally picks up hook changes automatically" (hooks-guide); if not, "restart your session to force a reload".
- Trust: interactive sessions hold back settings-file hooks "until you accept the workspace trust dialog" (hooks.md).
- Windows: shell-form hooks run in "Git Bash on Windows, or PowerShell when Git Bash isn't installed"; profile echo output breaks JSON: "The combined output no longer starts with `{`, so Claude Code treats all of stdout as plain text and ignores the JSON. On exit 0 nothing is reported" (hooks-guide). In a PowerShell hook "Don't write the bare `$CLAUDE_PROJECT_DIR` spelling... resolves it to `$null`" (hooks.md).
- Stop cap: "Claude Code overrides a Stop hook after it blocks eight times in a row with no tool call from Claude in between" (hooks-guide); raise with `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` (hooks.md). Stop input has `stop_hook_active`, `last_assistant_message`, `background_tasks` (hooks.md).
- Stop also covers shell-side edits: "If your hook must see every file change... add a `Stop` hook that scans the working tree once per turn" (hooks-guide).
- Hooks in skills/agents: "hooks can be defined directly in skills and subagents using frontmatter"; "Subagent hooks: Claude Code runs them only while that subagent is running"; "Skill hooks: ... keeps running them for the rest of the session"; `once: true` "Only honored for hooks declared in skill frontmatter" (hooks.md). "Hooks from settings files, managed policy settings, and plugins also run inside subagents" (hooks.md).
- `if` filter: "Only evaluated on tool events"; "the `if` filter is best-effort, use the permission system rather than a hook to enforce a hard allow or deny" (hooks.md).
- PreToolUse deny holds in every mode: "A hook that returns `permissionDecision: "deny"` blocks the tool even in `bypassPermissions` mode" (hooks-guide).
- UserPromptSubmit also fires on non-owner turns: "A scheduled task firing", "A background subagent reporting back to the session that started it", "A message another session sends" (hooks.md).

## 2. Skills (skills.md)

Key facts quoted:
- Loading: "a skill's body loads only when it's used"; descriptions always listed; "the combined `description` and `when_to_use` text is truncated at 1,536 characters in the skill listing".
- Live edits: "Claude Code picks up the change within the current session, without a restart" (project `.claude/skills/`); "Live change detection covers `SKILL.md` text only"; a new top-level skills directory needs `/reload-skills`.
- Compaction: "Claude Code re-attaches the most recent invocation of each skill after the summary, keeping the first 5,000 tokens of each. Re-attached skills share a combined budget of 25,000 tokens"; "Claude Code does not re-read the skill file on later turns".
- THE key line for pain P1: "Claude skipped a rule that must hold every time: move the rule into a hook. Claude Code runs a hook every time its event occurs... whether or not Claude is following the skill" (skills.md troubleshooting).
- After compaction: "invoke the skill again to restore its full content... put the most important instructions near the top of `SKILL.md`".
- Dynamic context (exclamation mark + backticked command): "runs shell commands before the skill content is sent to Claude. The command output replaces the placeholder".
- Bundled skills: "/doctor, /code-review, /batch, /debug, /loop, and /claude-api"; "/verify, run only when you invoke them".
- Frontmatter of note: `disable-model-invocation`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork`, `agent`, `hooks`, `paths`, `shell` (bash or powershell).
- Validation: "`claude plugin validate .claude/skills`... Requires Claude Code v2.1.233 or later".

## 3. Subagents (sub-agents.md) and parallel agents (agents.md)

Key facts quoted:
- Frontmatter: `tools`, `disallowedTools`, `model` ("`sonnet`, `opus`, `haiku`, `fable`, a full model ID... or `inherit`"), `permissionMode`, `maxTurns` ("returns its output marked as partial"), `skills` ("The full skill content is injected"), `mcpServers`, `hooks`, `memory`, `background`, `effort`, `isolation: worktree`, `omitClaudeMd`, `initialPrompt`.
- `memory`: "gives the subagent a persistent directory that survives across conversations"; `project` scope = `.claude/agent-memory/<name-of-agent>/` "shareable via version control"; "`project` is the recommended default scope"; "the first 200 lines or 25KB of `MEMORY.md`" go into its prompt; "Read, Write, and Edit tools are automatically enabled".
- Mid-session: "Claude Code detects the change within a few seconds and the next delegation uses the updated definition, with no restart needed", EXCEPT "after creating a scope's first agent file in a new `agents` directory, restart to load it". So a new agent file in our existing .claude/agents/ loads without restart; only the first file of a brand-new agents directory needs a restart.
- Trust: project subagent frontmatter hooks are skipped "Until you trust the folder"; "trusting a parent folder isn't enough, and a `-p` session doesn't count as trusted".
- Isolation: "It doesn't see your conversation history, the skills you've already invoked, or the files Claude has already read."
- Nesting: "a subagent can spawn subagents of its own, up to three layers below the main conversation".
- Cost: "Control costs by routing tasks to faster, lower-cost models like Haiku"; subagent requests "count toward the same usage limits".
- Priority: project `.claude/agents/` beats `~/.claude/agents/`, which beats plugin `agents/`.
- agents.md: five ways to parallelize; "Agent teams... Experimental and disabled by default"; "Projects... should keep running when your machine is off... Public beta on Pro and Max"; "Dynamic workflows: ...you want findings verified against each other"; "Running several sessions or subagents at once multiplies token usage".

## 4. Plugins: overview and code intelligence (plugins/overview.md, plugins/code-intelligence.md)

Key facts quoted:
- "A Claude Code plugin is a directory of skills, agents, hooks, MCP servers, or other components that Claude Code installs and loads as one unit."
- "Skills, subagents, hooks, and MCP servers all work on their own, without a plugin... Use a plugin when you want several... packaged as one unit."
- Cost of every enabled plugin: "An enabled plugin is part of every session, not only the sessions where you use it"; names and descriptions "are in Claude's context on every turn... Those tokens count toward your usage"; official marketplace plugins "show a **Context cost** estimate"; the Installed tab's "**Not used recently** group lists plugins you could turn off".
- Scopes: "Project scope: enabled for everyone who works in this repository, through the committed `.claude/settings.json`".
- Trust: "Whatever the tier, a plugin you install can run code with your user privileges."
- Code intelligence: "Claude catches type errors and missing imports that its own edits introduce before you run your build"; "each time Claude edits or writes a file the server handles, Claude gets the errors and warnings the server reports. It sees a type error, missing import, or syntax error it introduced without running a compiler."
- JavaScript is covered: "TypeScript and JavaScript | `typescript-lsp` | `typescript-language-server`"; binary: "`npm install -g typescript-language-server typescript`"; install: "`/plugin install typescript-lsp@claude-plugins-official`" (desktop app: follow "Install a plugin").
- Surface: "Code intelligence plugins work in terminal sessions. In cloud sessions, Claude Code doesn't start plugin language servers". Desktop app is named as an install surface.
- Proof it works: "`Found N new diagnostic issues in M files (ctrl+o to expand)`"; missing binary shows "`Executable not found in $PATH`" in the `/plugin` Errors tab.
- Cost: "High memory use: memory use increases while the server indexes the project."
- Not on the page: how many errors it finds in plain .js with no jsconfig. (From general TypeScript knowledge, NOT verified on these pages: plain .js gets syntax and import errors; type errors need a jsconfig.json with `checkJs`. Treat as unverified until tried.)

## 5. Plugins: install, loading, security (plugins/install.md, plugins/loading.md, plugins/security.md)

Key facts quoted:
- Desktop app: "Click the **+** button next to the prompt box and select **Plugins**, then **Add plugin**"; later "**+ > Plugins > Manage plugins**"; "The plugin browser isn't available in the desktop app's cloud sessions" (install.md).
- One machine, one set: "The terminal, the desktop app's local sessions, and the VS Code extension on one computer read the same settings files" (install.md).
- Footprint per plugin: "run `claude plugin details <name>`... The `Always-on` line is the number of tokens the plugin adds to every session where it's enabled" (install.md); details pane shows "**Every turn**" and "**When invoked**" token estimates for official plugins.
- Disable for this repo only: "To opt out of a project-enabled plugin on your machine, set the id to `false` in .claude/settings.local.json" (loading.md). Synced plugins: "`claude plugin disable <name>@synced`... To keep the plugin out of a project in every environment, set the same key in the project's committed `.claude/settings.json`" (loading.md).
- Load timing: "Changes to settings or to disk don't reach this layer until you run `/reload-plugins` or start a new session" (loading.md). Reload can cost: "If the reload would invalidate the prompt cache, it warns and leaves the plugin pending" (install.md).
- Auto-update: official marketplace "On by default"; "the files you reviewed can change on disk" (security.md); updates land "after you send your first message... a random delay of up to ten minutes" and apply next launch (loading.md).
- Security: "A Claude Code plugin you install can execute arbitrary code on your machine with your user privileges"; "Claude Code runs hooks, monitors, MCP servers, LSP servers... outside the sandbox"; official warning: "Anthropic does not control what MCP servers, files, or other software are included in plugins and cannot verify that they will work as intended or that they won't change" (security.md).
- Review before install: read `hooks/hooks.json`, `.mcp.json`, every file in `bin/`; "The **Will install** section shows that a hook exists but not what it runs" (security.md).
- Mentioned, not read: "The `security-guidance` or `claude-security` plugins... See security-guidance and claude-security" (security.md) - two Anthropic security plugins worth a separate look for P4.

## 6. Marketplaces, components, mods (plugins/anthropic-marketplaces.md, plugins/components.md, plugins/mods/overview.md)

Key facts quoted:
- Three Anthropic marketplaces: official `claude-plugins-official` ("Plugins Anthropic maintains, plus plugins from partners and other authors"), community `claude-community` ("Third-party plugins that their authors submitted to Anthropic"), demo `claude-code-plugins`. "Most of what it lists comes from partners and other authors rather than from Anthropic"; Anthropic maintains "`commit-commands`, `code-review`, `feature-dev`, and the language server plugins". "`security-guidance` ... in both" demo and official. "Anthropic doesn't review third-party marketplaces". Claude Marketplace on the web "marks some plugins **Anthropic verified**" (anthropic-marketplaces.md). Hookify is not named on this page; whether it is Anthropic-maintained must be checked in /plugin details before install.

## 8. MCP (mcp.md) and built-in tools (tools-reference.md)

Key facts quoted:
- "Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk" (mcp.md).
- Project servers: "Claude Code prompts for approval in interactive sessions before using project-scoped servers from `.mcp.json` files"; but "In `claude -p` runs... cloud sessions, Claude Code can't show that prompt: it loads project-scoped servers without asking"; `disabledMcpjsonServers` "blocks it in every permission mode" (mcp.md).
- Secrets: "environment variable expansion in `.mcp.json` files... sensitive values like API keys" - write `${SUPABASE_...}`, never the key itself (mcp.md).
- Per-project off switch: "Toggle a server off in the `/mcp` panel... stored per project in `~/.claude.json`, in the `disabledMcpServers` list"; block one claude.ai connector with `deniedMcpServers`; all with `"disableClaudeAiConnectors": true` (mcp.md).
- Output cap: "warning when MCP tool output exceeds 10,000 tokens and limits output to 25,000 tokens by default" (mcp.md).
- Tool search is on by default: "Only tool names and server instructions load at session start, so adding more MCP servers has minimal impact on your context window" (mcp.md).
- Approval on every call exists only server-side: `_meta["anthropic/requiresUserInteraction"]` "shows that tool's permission prompt on every call, even in `acceptEdits`, `auto`, and `bypassPermissions`" - set by the server author, not by us (mcp.md).
- Plugin MCP tool names: `mcp__plugin_<plugin-name>_<server-name>__<tool-name>`; "A hook matcher written against the bare server key... never fires for a plugin-bundled server" (mcp.md). In this session the Supabase connector appears as `mcp__607c535c-...__execute_sql`, `apply_migration`, `delete_branch`, `pause_project` etc. and also a `plugin:supabase:supabase` server - two names to match.
- LSP tool: "After each file edit, it automatically reports type errors and warnings so Claude can fix issues without a separate build step"; "Claude Code keeps the tool inactive until you install a code intelligence plugin" (tools-reference.md).
- Monitor tool: "feeds each output line back to Claude"; deadline "5 minutes by default, at most 30 minutes"; "On Windows, the tool is available only when Git Bash is installed" (tools-reference.md).
- PushNotification tool: "Sends a desktop notification, and a phone push when Remote Control is connected" (tools-reference.md).
- Windows trap: "On Windows with Git Bash installed, denying Bash also turns the PowerShell tool off for the session... Claude Code turns PowerShell off without a warning" unless `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` or a scoped PowerShell rule is added (tools-reference.md).
