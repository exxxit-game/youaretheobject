## 3. Local scheduling (Desktop scheduled tasks, /loop)

Tip: "Use cloud tasks for work that should run reliably without your machine. Use Desktop tasks when you need access to local files and tools."

## Top 5 for us now

1. **Automatic independent review of every PR on GitHub, on the subscription**: GitHub Action review workflow (`/install-github-app`, choose the review workflow; secret `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token` so "runs use your Claude subscription instead of API billing"; add `--max-turns` and a workflow timeout). Runs on GitHub's machines with the repo's CLAUDE.md, outside the writing session. Caveat: it skips PRs "that already have a comment from Claude" -- test whether later pushes get re-reviewed. Alternative with the same effect: a routine with a GitHub `pull_request` trigger. Managed Code Review is Team/Enterprise only and $15-25 per review -- not for us.
2. **Cloud routine for the daily morning check (and a weekly check)**: runs "when your laptop is closed", minimum 1 hour interval, on subscription usage; repo hooks/agents/skills travel with the clone, the owner's local auto-memory does not. Must write a checkable verdict (issue, file, or status artifact), because "A green status ... does not mean the task in your prompt succeeded". Needs Custom network access for `*.github.io` (live site) and Supabase. Keep a Desktop **Local** task (worktree toggle on, permissions pre-approved) only for jobs that need the laptop or headset; it catches up once after a power cut.
3. **Cloud sessions for long work across power cuts**: Desktop "Open in" sends a local session to the cloud; "no separate charge for the cloud VM"; push before moving (cloud clones the remote, not the local checkout). Pair with **Auto-fix** on the PR so CI failures (smoke test runs only in GitHub Actions) are fixed without the laptop.
4. **Local `/code-review` as the cheap per-step independent check** (subagent with its own context, follows CLAUDE.md, counts toward normal usage), with **ultrareview** (`/code-review ultra <PR>`) only before a batch goes to main: 3 free runs on Pro/Max, then $5-25 each in usage credits; it cannot be started by Claude on its own.
5. **Owner-facing visibility without reading code**: one private **artifact** status page kept current (by the session or the morning routine) that the owner opens on his phone; owner checks plan use at claude.ai/settings/usage; assistant uses `/usage` (what eats the plan) and `/insights` (friction and repeated mistakes) as inputs to docs/mistakes.md. Keep usage credits OFF unless the owner decides, so nothing bills extra by accident.

## Top 5 for later

1. **Projects** (public beta, Pro/Max, rolling out): one coordinator conversation with cloud threads, project memory every thread reads, Overview of what needs the owner, PR auto-fix -- the closest built-in answer to "long sessions lose details" and "owner away". Try when it reaches the account; watch plan usage ("uses them faster").
2. **Saved dynamic workflows** in .claude/workflows/ for fixed multi-agent checks (room verification: paper-reviewer + architecture-auditor + two independent fact-checkers), plus `/deep-research` for rule-23 source research; size guideline small on Pro.
3. **Scripted reviewers with hard limits**: `claude -p` with `--json-schema` (machine-readable verdict a hook can enforce), `--max-budget-usd`, `--max-turns`, `--permission-prompts none`; cost logged from `total_cost_usd`.
4. **Agent teams** (experimental) for adversarial "competing hypotheses" debugging and `TaskCompleted`/`TeammateIdle` hook gates -- only when single-session subagents are not enough; ~7x tokens in plan mode per costs.md.
5. **Team-scale tooling when testers/staff arrive**: managed Code Review with REVIEW.md and spend cap (Team plan), analytics dashboard, OpenTelemetry cost metrics, organization-shared cloud environments, cross-session messaging between parallel worktree sessions, API-triggered routines (e.g. from CI or monitoring alerts).
