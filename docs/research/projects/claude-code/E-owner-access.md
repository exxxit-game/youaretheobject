## Part 5. Coordinator question: which branch a NEW Desktop worktree session starts from (W = https://code.claude.com/docs/en/worktrees)

- Default = the remote default branch (main), not the branch he is working on. W#choose-the-base-branch: "New worktrees branch from the repository's default branch"; `"fresh"` (default): "branch from the repository's default branch on the remote, usually `main`, so the worktree starts from a clean tree matching the remote." It fetches first: "when the repository hasn't been fetched in the last 24 hours, it fetches the default branch". This is why this session started on old main code.
- Desktop uses git worktrees the same way: ".worktreeinclude ... applies to every worktree Claude Code creates with git: `--worktree` worktrees, subagent worktrees, and parallel sessions in the desktop app" (W#copy-gitignored-files-into-worktrees). The base-branch section itself does not name Desktop; that Desktop obeys `worktree.baseRef` is an inference from D#shared-configuration ("Desktop and CLI read the same configuration files") and "The desktop app reads the same settings files as the CLI" (D#choose-a-permission-mode). Verify once.
- To start from current work: `worktree.baseRef: "head"`: "branch from your current local `HEAD`, so the worktree carries your unpushed commits and feature-branch state". "Inside a worktree, `"head"` resolves to that worktree's `HEAD`, not the main checkout's." Example: `{ "worktree": { "baseRef": "head" } }` in settings.
- No branch name allowed: "You can't set `worktree.baseRef` to a branch name. To start a worktree from a specific existing branch, create it with git directly" (`git worktree add ../project-bugfix fix-issue-456`).
- Desktop UI: D#work-in-parallel-with-sessions: "Click **+ New session** in the sidebar, or press ... **Ctrl+N** on Windows ... For Git repositories, select the **worktree** option next to the branch name to give the session its own isolated copy of your project". The docs do NOT describe choosing a different base branch in that control, and do NOT say what happens with the option off; by the wording, without "worktree" the session works directly in the project folder on whatever branch that folder has checked out (inference; verify on screen).
- Other Desktop worktree settings: "Settings → Claude Code under 'Worktree location'"; "a branch prefix that gets prepended to every worktree branch name".
- Task chips: "Click the chip to start that work in a new session with its own worktree" (D#work-across-sessions); same base rule.
- Traps: reusing a worktree name with "fresh" resets it to main when it has no own commits and no uncommitted files (W#reuse-a-worktree-name). Archiving a Desktop session removes its worktree: "To remove a worktree when you're done, hover over the session in the sidebar and click the archive icon" (D).
- Exact clicks, as far as the docs go: 1) Sidebar "+ New session" (Ctrl+N). 2) Environment "Local", folder = the objekt project. 3) Next to the branch name, turn on "worktree". 4) If the new session must start from unfinished work and not from main: once, the assistant adds `"worktree": {"baseRef": "head"}` to the project `.claude/settings.json`; then the worktree starts from the HEAD of the folder the session is opened in (the main checkout), so that folder must be on the right branch. Simplest alternative: keep finished work on main (or pushed and merged) often, so "fresh" main is current.

## Top 5 for the owner now (plain steps)

1. Update first. In the Claude app on the laptop: menu **Help** > **Check for Updates**. Then open a new session in the **Code** tab and type `/status`; the row "Claude Code" shows the version (newest in the docs: 2.1.295 of 8 Oct 2026). Old sessions keep the old version, so start a new one.
2. Phone follows every session by itself. Laptop: **Settings** > **Claude Code** > turn on **Connect new sessions to Remote Control**. Phone: install the **Claude** app (same account), tap **Code**: the laptop session has a computer icon with a green dot. Write or dictate there (the phone keyboard microphone), approve questions there. The laptop must stay on with the app open; after a power cut, open the app and the session again and it reconnects.
3. Push to the phone when work is done or a decision is needed. Phone: allow notifications for the Claude app (Android: exclude it from battery saving). Turn on "Push when Claude decides" and "Push when actions required" (the docs name these `/config` toggles; in Desktop `/config` opens Settings > Claude Code, where they should be: the assistant checks this on screen with him once). You can also just write "notify me when it is done".
4. Stop or steer without fear. Stop at once: the stop button or **Esc**. Correct while it works: type the correction and press Enter, it does not stop the work. Ask "what are you doing?" without disturbing it: **Ctrl+;** (side chat). See and stop running helpers: **⋮** menu > **Background tasks**. For a big change: choose **Plan** in the mode selector next to the send button, so nothing is changed until he approves the plan.
5. Approve designs as pictures. Ask "/design" plus a short brief (or ask the assistant for an artifact page): the assistant gets a link to a page with design options, opens on the phone, he picks one by number. Pictures and PDFs named in the chat open in the built-in Browser pane with one click. Turn on **Auto-continue when limits reset** the next time a limit card appears, so work resumes by itself.

Not recommended now: Telegram channel (terminal-only, research preview, needs Bun and a terminal kept open, dies with each power cut); Slack/Claude Tag (cloud, team plans); deep links (open a terminal, not the phone); voice `/voice` (terminal-only per the docs, though Russian is supported); fullscreen/keybindings (terminal-only).

Open questions to verify on screen (docs silent): whether Desktop Settings shows the two push toggles; whether the Desktop Code tab has voice input; whether Desktop has a rewind/checkpoint button; whether Desktop new-session worktrees follow `worktree.baseRef: "head"` and what the session does with the worktree option off.
