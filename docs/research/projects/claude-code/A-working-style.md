# A. Working style: Claude Code docs vs the "You are the object" project

Research date 2026-10-09. Pages fetched as raw markdown from https://code.claude.com/docs/en/<page>.md.
Every quote is copied from the page. "Use" column: what I could see in the repo (CLAUDE.md is 100 lines / 7,870 bytes;
.claude/ holds agents/, skills/, settings.json with a PreToolUse and a Stop hook, launch.json; NO .claude/rules/,
NO output-styles/, no statusLine in project settings; MEMORY.md index is 14 lines / 1,823 bytes). User-level settings
(~/.claude/settings.json) were not read, so anything that would live there is "unknown".

Legend for value: NOW = adopt in the current work, LATER = useful once something else is in place, NO = does not fit.

## Top 5 for us now

1. **SessionStart hook with the `compact` matcher (+ a "Compact Instructions" section in CLAUDE.md)** - after every compaction a small script prints the current queue step and the open owner requests from docs/state.md into the new context; this turns rule 22d from memory into a mechanism, directly against pain 2 (context-window.md: hooks matching `compact` "adds their output to the compacted context").
2. **`/goal` for each queue step, with a proof-bearing condition and a turn cap** - a separate model judges "done" after every turn from evidence Claude printed (npm test exit 0, git status clean, request rows written); restored on resume after power cuts; against pains 1 and 3 (goal.md).
3. **Slim CLAUDE.md where it costs nothing and move procedures out** - run `/doctor prompt-audit`; keep must-persist rules in the root file (path rules and nested files are lost at compaction), move room/paper procedures to the new-room skill (most important text at its top: only the first 5,000 tokens survive compaction); remember a CLAUDE.md edit reaches the running session only after `/clear`, `/compact` or restart, so a rule-19 guard must be a hook to bite now (pains 1, 2, 5; memory.md, prompt-caching.md, context-window.md).
4. **Client-enforced protection: `permissions.deny` Read rules for secrets and `vendor/`, `/security-review` on every branch touching data** - CLAUDE.md is "a request, not a guarantee"; deny rules are enforced, and `/security-review` checks "data exposure" (pain 4, and pain 5 for vendored A-Frame) (features-overview.md, large-codebases.md, commands.md).
5. **The owner's own levers: Remote Control from his phone, `/recap`, `/btw`, queued messages** - his phone message lands in the live laptop session; `/recap` (max 400 characters, cache-safe) gives him status without reading logs; `/btw` answers a quick question without growing context; queued messages are not lost while Claude works (pains 2, 3, 5; glossary.md, interactive-mode.md). Remote Control and `/voice` in the desktop app must be tested first.

## Top 5 for later

1. **Custom output style for owner reports** (Russian, plain words, done / how checked / next; `keep-coding-instructions: true`) - survives compaction like the system prompt and frees CLAUDE.md lines; test against the Concise built-in first (output-styles.md).
2. **Advisor tool (`/advisor opus`)** - a second Opus at decision points, before "done" and on recurring errors (pain 1); measure cost first, since each call re-reads the full transcript uncached (advisor.md).
3. **Lower auto-compact window, measured** (`/autocompact`), paired with item 1 above - earlier, smaller compactions instead of letting a 1M window fill to ~967K where quality degrades (model-config.md, best-practices.md).
4. **Raise `cleanupPeriodDays` and archive transcripts with a SessionEnd hook / `/export`** - the request-auditor needs old owner messages; transcripts are deleted after 30 days by default (sessions.md).
5. **Visibility and periodic review: status line with context % and plan-limit %, `/usage` attribution, `/insights` monthly** - shows which agents and MCP servers eat the plan and where sessions go wrong; status line support in the desktop app is unverified (statusline.md, costs.md).
