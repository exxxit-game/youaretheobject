# Testing

| Command | What | Where to run |
|---|---|---|
| `node tools/secrets.mjs [range]` | No key, token or own email in the commits about to be pushed; git runs it before every push (`tools/hooks/pre-push`, set once per clone: `git config core.hooksPath tools/hooks`), and `tools/publish-preview.mjs` on the copy it pushes; `--staged`: what the next commit adds (`tools/hooks/pre-commit`) | Locally, by git |
| `tools/hooks/pre-commit`, `tools/hooks/pre-push` | No commit past the quick check (seconds): nothing private staged, every staged script parses, the quick tests of `npm test` pass (all but the slow structure and review-gate tests, which run in `npm test` before "done" and on GitHub); a feature turned to passing (or dropped) only with the owner's acceptance in his log naming its number in the list (CLAUDE.md step 5) (`tools/claude-guard.mjs accepted`); main (the live site) is held by its GitHub rule, not by a hook; `tests/secrets.test.mjs` runs both hooks and the secret check on real commits | Locally, by git |
| `node tools/prove-guards.mjs [--lf]` | Every guard seen going red: in a clone of the last commit it plants, one at a time, the mistake each structure check and git hook exists for, runs that guard and puts the clone back; a guard that stays green is reported BLIND (exit 1). `--lf` checks with plain line ends as on GitHub, without it the laptop's own (CRLF) | Locally after a change to a guard; on GitHub on every push to room-polish or main |
| `tools/claude-guard.mjs` | Run by Claude Code itself (`.claude/settings.json`), not by the assistant's memory: a shell command that skips the git hooks, runs Playwright locally, restarts the headset, writes the practice review record, deletes in the papers library or merges into main is refused (the command read as the shell reads it, each program judged by its arguments, never by words in quotes, messages or heredocs); a connected tool banned by name is a deny rule in the settings; a new window's start names the current feature, gives the owner his measure (features accepted in 7 days, yesterday's commits to the game and to the process) and brings a copy behind room-polish up to it; every owner message is appended to Documents/objekt-files/notes/owner-messages.md on the laptop; `tests/guard.test.mjs` runs it on real commands both ways: what it stops is refused in every form the shells write it, and a command that only reads, searches or names those words passes | Locally, by Claude Code |
| `npm test` | Node only, about 30 s on the laptop (the commit hook runs its quick part): structure rules (`tests/structure.test.mjs`, docs name no constant the code lacks), the room protocol pinned to the paper, schedule, report, reveal pages, every recording and sound present (and every corridor sound has a measured gain), file names safe from ad blockers, VR recenter math, tile and block layout (`tiles`, `masonry`), the building standards (`standards`), the sign's flash safety and endings (`glow`), the clipboard's trips (`sheet`), the studio's mark (`logo`), thumbstick moving (`locomotion`), door plaques (`plaque`), the guard on the assistant's commands (`guard`) | Anywhere, locally too |
| `npm run test:smoke` | `tests/smoke.mjs`: headless Chromium plays the default room at 20× speed: the sign, taking the clipboard from the board, the corridor/desk light ratio, no faces under 5 mm apart that flicker (`tests/near-faces.mjs`: corridor, signed form, room), consent, the room to the last reveal page, and a playtest pass with `?sign=b`; then the same game in VR on Meta's emulated Quest 3 (`tests/smoke-vr.mjs`, IWER, each eye 110° × 96°): the clipboard taken with the right controller's trigger along its ray, and each place's worst view held at its draw calls a frame, both eyes (`tests/draw-calls.mjs`: corridor under Quest 2's 100, room 101 held under 150); fails on any console error | GitHub Actions only (heavy) |
| `node tools/check-voice.mjs <room>` | Speech-to-text of every recording compared with the script (wrong or skipped words) | Locally, costs ElevenLabs credits |
| `node tools/quest-check.mjs` | Plays the corridor (the clipboard, the two-page form with its seal, the age, door 1) and the room in the headset at 10× speed; fails on any page error; its frame rate is told, not judged (the flat page in the browser window paces itself; the VR bar is quest-look perf's); wakes the headset and puts it to sleep after | Locally, headset on its cable, the preview running |
| `node tools/quest-look.mjs <command>` | In the headset on its USB cable, without the owner: `open` (the test copy) or `open local [port]` (the laptop's server, the preview's port by default, seen by the headset as localhost:3000), `sleep` (ends every check: the laptop charges it slowly), `reload` (past caches), `ask "<question>" "<answer>"…` (a question in the headset, its answers as buttons pressed with the controller's ray; prints his answer: while he wears it nothing waits on the chat), `end "<step>"` (the look's last step; once the headset is off, the HUD off and asleep), `vr` (enter VR with OVR Metrics' HUD asked on first, refused if the request is not delivered; `sleep` and `end` ask it off; only while the owner wears the headset: on a table the boundary window holds the request and the browser then refuses VR until it restarts), `frame out.png` (what the headset shows, both eyes, by its own screen capture: reading the page came out black with multiview), `eval "<js>"`, `worn on|off` (keep it awake while checking), `levels` (each corridor sound at its game gain and a voice line measured at the output; fails outside the mix: events at most 12 dB under the voice, the hum 15–30 dB under it), `perf` (five seconds of frames: rate, slow frames, draw calls, triangles; fails under 72 fps or at 100 draw calls or 750,000 triangles, Meta's Quest 2 budget, the weakest headset's), `restart-browser` (the cure when every request to enter VR fails with NotSupportedError: the browser lost its link to the VR system) and `reboot`, both refused while the owner wears the headset | Locally, headset linked over Wi-Fi |
| `node tools/publish-preview.mjs` | Publishes the game files to the test copy the headset opens (exxxit-game.github.io/object-preview); never the live site | Locally, before a headset check |
| `node tools/quest-wifi.mjs` | Links the headset over Wi-Fi for the tools above, only when the cable is out | Locally |
| `node tools/xr-probe-run.mjs [vr ar mic]` | Presses the capability probe's buttons (`tools/xr-probe.html`) in the headset and prints what WebXR gave; VR and MR only while the owner wears it | Locally, headset on its cable |
| `node tools/check-cards.mjs`, `node tools/build-catalog.mjs` | Every experiment card's quotes are found in its paper; the catalog is built from the cards (`--check`: up to date) | Locally |
| `node tools/make-voice.mjs`, `node tools/make-sounds.mjs` | Recordings and sounds made from the texts and the sound lists | Locally, costs ElevenLabs credits |
| `node tests/static-server.mjs` | Local preview at http://localhost:3000 (`npm run serve`); the app's preview pane serves it on the port in `.claude/launch.json` (3100), which the headset tools read | Locally |

`?speed=N` (1–100) makes every timing N times faster; such runs are never sent.
Before saying "done", report which of these ran and what they printed.
A new rule in a pure module needs its test first (red), then the change (green).
